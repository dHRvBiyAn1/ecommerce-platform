Implementation Approaches

Two strategies for replacing Zard UI with PrimeNG + Sakai

A

Big Bang — Replace Everything

In one sequence: install PrimeNG deps, remove Zard entirely, create Sakai layout, rebuild all 13 pages with PrimeNG components.

Pros

  • Fastest total time
  • Clean break — no hybrid state
  • You see the full result at once

Cons

  • App is broken until complete
  • Hard to debug issues across 13 pages
  • Large diff — harder to review
B

Phased — Sakai Layout First, Then Pages

Phase 1: Install PrimeNG, create Sakai layout shell (topbar + sidebar + footer) + admin dashboard, remove Zard. Phase 2: Migrate public pages. Phase 3: Migrate seller pages. Phase 4: Polish.

Pros

  • App works at each phase
  • Easier to debug incrementally
  • Smaller diffs per PR

Cons

  • Takes more total steps
  • More coordination between phases

★ My recommendation — safer, verifiable at each step

What Both Approaches Share

Regardless of approach, the PrimeNG MCP server setup is the same:

npx -y @primeng/mcp

This gives us AI-assisted access to PrimeNG component docs, props, events, and code examples throughout the migration.
